# 러닝 다이제스트

매일 출근길(08:00 KST)과 퇴근길(19:00 KST)에 러닝 관련 뉴스와 유튜브 영상을
텔레그램으로 보내주는 봇. GitHub Actions에서 돌기 때문에 서버가 필요 없다.

설계 배경과 단계별 계획은 [PLAN.md](PLAN.md) 참고.

## 설정하기

### 1. 봇 만들고 토큰 등록

1. 텔레그램에서 `@BotFather` 와 대화 → `/newbot` → 봇 토큰 발급
2. 레포 **Settings → Secrets and variables → Actions → New repository secret**
   에 `TELEGRAM_BOT_TOKEN` 으로 등록

워크플로는 `TELEGRAM_BOT_TOKEN` 과 `RUNNING1978XIANAO_BOT` 두 이름을 모두
받는다. 앞의 것이 비어 있으면 뒤의 것을 쓴다. 새로 만들 때는
`TELEGRAM_BOT_TOKEN` 을 권한다.

토큰은 절대 `config.yaml` 이나 코드에 적지 않는다. Secrets 에만 넣는다.
토큰이 노출됐다면 BotFather 에서 `/revoke` 로 폐기하고 새 토큰을 발급받아
같은 시크릿의 값을 갱신한다. 봇과 설정은 그대로 유지된다.

### 2. chat_id 찾기

`getUpdates` URL 을 직접 열 필요 없다. 워크플로가 대신 찾아준다.

1. 만든 봇에게 텔레그램에서 아무 메시지나 전송
   (getUpdates 는 최근 24시간 기록만 보관하므로 이 순서가 중요하다)
2. **Actions → chat_id 확인 → Run workflow** 실행
3. 로그에 나온 숫자를 `TELEGRAM_CHAT_ID` 로 등록

```
찾은 채팅방:
  TELEGRAM_CHAT_ID = 123456789    ← 홍길동 · private
```

**봇은 보낸 메시지에 답하지 않는다.** 수신 메시지를 처리하는 코드가 없는
단방향 봇이다. 1번에서 반응이 없는 것이 정상이고, 메시지가 전송되기만 하면
된다. 대신 2번을 실행하면 봇이 확인 메시지를 한 번 보내주므로 연결이
제대로 됐는지 텔레그램에서 눈으로 확인할 수 있다.

### 3. 한국어 요약 켜기 (선택)

영어 기사·영상의 제목을 한국어로 번역하고 1~2문장 요약을 붙이려면
Claude API 키를 Repository secrets 에 추가한다. 워크플로는
`ANTHROPIC_API_KEY` 와 `RUNNING_API` 두 이름을 모두 받는다 (앞의 것이
비어 있으면 뒤의 것을 쓴다).

키가 없으면 요약 단계를 건너뛰고 제목과 링크만 보낸다. 발송 자체는
실패하지 않는다. 요약 요청이 실패해도 마찬가지로 제목만 나간다.

`config.yaml` 의 `summary.enabled` 로 끄고 켤 수 있고, `summary.effort` 로
비용과 품질을 조절한다 (`low` 기본값).

### 4. 유튜브 영상 켜기 (선택)

채널 RSS(`youtube.com/feeds/videos.xml`)는 GitHub Actions 러너에서 404/500 을
자주 돌려준다. 같은 채널 ID가 실행마다 다른 오류를 내므로 ID 문제가 아니라
유튜브 쪽에서 러너를 막는 것으로 보인다. 영상을 안정적으로 받으려면
YouTube Data API 키를 쓴다.

1. Google Cloud Console 에서 프로젝트 생성 → **YouTube Data API v3** 사용 설정
2. 사용자 인증 정보 → API 키 만들기 (결제 등록 불필요)
3. Repository secrets 에 **`YOUTUBE_API_KEY`** 로 등록

호출은 채널당 1 유닛이고 일일 쿼터는 10,000 이다. 채널 48개 + 주제 5개의
영상 검색(각 100 유닛)을 합쳐도 하루 600 유닛 남짓이라 여유가 크다. 키가 없으면 RSS 로 시도하고, 실패하면 영상 없이
기사만 보낸다.

### 5. 첫 발송 확인

**Actions → 러닝 다이제스트 → Run workflow** 에서 수동 실행.
`dry_run` 을 켜면 실제 전송 없이 로그로 메시지만 확인할 수 있다.

시크릿이 아직 없어도 실행은 된다. 전송만 건너뛰고 수집 결과와 완성된
메시지를 로그에 출력한 뒤, 무엇이 빠졌는지 에러로 알려준다. 소스가
제대로 동작하는지는 설정을 마치기 전에도 이렇게 확인할 수 있다.

## 소스 추가·변경

`config.yaml` 만 고치면 된다. 커밋하면 다음 실행부터 반영된다.

### 유튜브 채널 추가

세 가지 방법이 있고, 결과는 `state/channels.json` 에 캐시되므로 채널당 한 번만
조회한다.

```yaml
sources:
  youtube:
    - name: 채널 이름                                   # 이름만 (API 키 필요)
    - name: 채널 이름
      url: https://www.youtube.com/@handle              # 주소로
    - name: 채널 이름
      channel_id: UCxxxxxxxxxxxxxxxxxxxxxx              # ID를 알면 바로
```

**이름만 적는 방법**은 `YOUTUBE_API_KEY` 가 있어야 하고, 검색이라 동명이인
채널이 잡힐 수 있다. 로그에 `'런랜드' 검색 → '런랜드 RUNLAND' (UC...)` 처럼
찾은 채널 이름이 찍히니 확인하고, 틀렸으면 `state/channels.json` 에서 해당
줄을 지운 뒤 `search:` 로 검색어를 좁히거나 주소를 직접 넣는다.

검색은 호출당 100 유닛으로 비싸지만 캐시되므로 채널당 한 번만 든다
(10개 등록 = 1,000 유닛, 일일 쿼터 10,000).

### 뉴스 검색어 추가

```yaml
sources:
  google_news:
    - name: 트레일러닝
      query: 트레일러닝 OR 울트라마라톤
      lang: ko
      country: KR
```

### 네이버 블로그

훈련 후기·코스·러닝화 리뷰처럼 뉴스에도 유튜브에도 없는 글이 여기 많다.

**검색 API 는 쓸 수 없다.** 네이버가 블로그·뉴스·카페 검색을 개발자센터에서
[NAVER API HUB](https://www.ncloud.com/product/applicationService/naverApiHub)
(네이버클라우드플랫폼)로 옮겼다. 그래서 developers.naver.com 의 **사용 API**
목록에 `검색` 이 더 이상 나타나지 않고, 거기서 받은 키로 호출하면
`[024] Scopes are Empty` 가 난다. 쇼핑·책·전문자료 검색은 2026년 7월 31일자로
아예 종료됐다.

`src/collect.py` 의 `search_naver_blog()` 와 `sources.naver_blog` 는 남겨뒀다.
HUB 규격(엔드포인트·인증 헤더)을 확인하면 그 자리에 다시 이으면 된다.
어느 config 에서도 쓰지 않으므로 지금은 아무 요청도 나가지 않는다.

**블로그별 RSS 는 그대로 된다.** 키도 계정도 필요 없다.

```yaml
sources:
  rss:
    - name: 어느 러너의 블로그
      url: https://rss.blog.naver.com/<블로그아이디>.xml
```

어드민 페이지의 주제 카드를 펴면 **네이버 블로그** 칸이 있다. 주소를
붙여넣으면 아이디만 뽑아 RSS 주소로 만들어 `settings.yaml` 의 `feeds` 에
넣고, 발송할 때 `sources.rss` 뒤에 붙는다. 받는 모양은 다음과 같다.

- `https://blog.naver.com/아이디/223456789`
- `m.blog.naver.com/아이디`
- `https://rss.blog.naver.com/아이디.xml`
- `@아이디` 또는 `아이디`

### 같은 내용을 두 번 보내지 않기

세 겹으로 막는다.

1. **id** — `state/<주제>/seen.json` 에 보낸 항목의 id 를 남긴다.
   유튜브는 영상 id, 뉴스는 기사 id.
2. **URL** — 한 회차 안에서 같은 URL 이 여러 소스에 잡히면 접는다.
   추적 파라미터는 `TRACKING_PARAMS` 에서 떼어내 같은 글로 인식시킨다.
3. **제목 지문** — 같은 사건을 여러 매체가 쓰면 id 도 URL 도 다르다.
   이건 1·2 로 안 걸린다.

지문은 이렇게 만든다.

```
"서울마라톤 접수 시작 - 연합뉴스"   매체명을 떼고
"서울마라톤 접수 시작"              두 글자 이상 낱말만 남겨
{마라톤, 서울마라톤, 시작, 접수}     정렬해 해시 → t:a1b2c3…
```

지문이 완전히 같으면 버리고, 낱말이 많이 겹치면(자카드 **0.7** 이상)
점수 높은 쪽만 남긴다. 지문도 `seen.json` 에 함께 남기므로 **어제 A매체로
나간 사건이 오늘 B매체로 다시 오지 않는다.**

```
[filter] 겹치는 항목 제외 4건 (지난 발송과 3 · 이번 회차 안에서 1)
```

`서울마라톤 접수 시작` 과 `서울마라톤 접수 마감` 은 겹침이 0.5 라 둘 다 남는다.

### 유튜브 영상 기준

```yaml
youtube_filter:
  min_subscribers: 10000    # 채널 구독자
  min_views: 5000           # 영상 조회수
```

수집한 뒤 `videos.list`(조회수)와 `channels.list`(구독자)로 확인한다.
id 를 50개씩 묶어 물어보고 호출당 1유닛이라, 영상 400건이라도 16유닛이면
끝난다. 구독자 수는 하루 사이에 변하지 않으므로 `channels.json` 에 7일간
캐시한다.

**구독자 기준은 검색으로 들어온 채널에만 적용한다.** `sources.youtube` 에
사람이 적어둔 채널(어드민에서 넣은 것 포함)은 건너뛴다. 크기를 보고 고른
목록이 아니기 때문이다. 조회수 기준은 직접 고른 채널에도 그대로 적용된다.

그래서 구독자 수는 모르는 채널에만 물어본다. 호출도 그만큼 줄어든다.

**확인하지 못한 값은 통과시킨다.** 요청이 실패했거나 채널이 구독자 수를
숨긴 경우다. 모르는 것을 이유로 버리면 API 가 한 번 흔들릴 때 영상이
통째로 사라진다.

> **조회수 기준과 신선도는 서로 당긴다.** 두 시간 전에 올라온 영상은
> 구독자가 많은 채널이어도 아직 1만 회가 안 된다. 기준을 올릴수록
> 들어오는 영상이 하루쯤 묵은 것으로 기운다. 새 영상을 놓치는 느낌이면
> `min_views` 를 먼저 낮춘다.

### 뉴스는 기간을 좁혀 부른다

구글 뉴스 RSS 는 검색어만 주면 **관련도순**으로 돌려준다. 몇 달 전 기사가
섞여 오고, 그것들은 `lookback_hours` 에서 전부 잘려 나간다. 주제에 따라
기사가 한 건도 남지 않는 일이 실제로 있었다 — 음식 회차에서 뉴스 210건을
받아 최근 것이 0건이었다.

그래서 검색어 뒤에 `when:` 을 붙인다. `lookback_hours` 에서 만들고, 나누어
떨어지지 않으면 **올림**한다(36시간 → `when:2d`). 좁혀서 빈손이면 제한 없이
한 번 더 부르므로, `when:` 이 안 먹는 경우에도 지금보다 나빠지지 않는다.

수집 로그도 종류별로 나눠 찍는다. 합계만 보면 기사가 통째로 잘려도
눈에 띄지 않는다.

```
[collect] 전체 435건 중 최근 36건 (기사 0 · 영상 36, 최근 48시간)
```

### 키워드로 영상 찾기 (채널 목록 밖)

`sources.youtube` 는 내가 적어둔 채널만 본다. 그 목록에 없는 채널이 올린
영상은 아무리 좋아도 들어오지 않는다. `youtube_search` 가 유튜브 전체를
대상으로 하는 통로다. 모든 config 에 하나씩 걸려 있다.

```yaml
sources:
  youtube_search:
    - name: 러닝 인기 영상
      query: 러닝 OR 마라톤 OR 달리기
      order: viewCount   # date(기본) · viewCount · relevance · rating
      lang: ko           # relevanceLanguage. 없으면 전 세계
```

`lookback_hours` 안에 올라온 영상만 본다. 여기에 `order: viewCount` 를
같이 쓰면 **최근 이틀 안에 많이 본 영상**이 되어, 모르는 채널이라도
반응이 좋은 것부터 올라온다. 정렬 이름을 잘못 적으면 그 회차를 잃지 않도록
`date` 로 떨어뜨리고 로그에 남긴다. `search` 호출은
**100 유닛**이고 캐시가 없어 회차마다 든다 — 검색어 하나 × 하루 2회면
200 유닛으로, 일일 쿼터 10,000 안에서 검색어 20개까지는 여유가 있다.
`YOUTUBE_API_KEY` 가 없으면 이 소스는 통째로 건너뛴다.

어드민 페이지에서 만든 주제는 **검색어 하나가 뉴스와 유튜브 양쪽에
걸린다.** 유튜브 쪽만 끄려면 그 검색어에 `youtube: false` 를 넣는다.

### 인기 채널 찾아 목록에 넣기

`youtube_search` 는 영상 단위로 넓히고, 이건 **채널 목록 자체**를 넓힌다.
주제로 채널을 찾아 구독자 수와 함께 출력한다. 아무것도 전송하지 않고
넣을지는 사람이 고른다.

```bash
python scripts/discover_channels.py 러닝 마라톤
python scripts/discover_channels.py --all      # settings.yaml 의 모든 주제
```

Actions 에서는 **인기 채널 찾기** 워크플로를 돌리거나 `.discover-trigger` 에
검색어를 적고 푸시한다. 이미 쓰고 있는 채널, 구독자 2만 미만, 영상 30개
미만은 빼고 보여준다. 출력이 `config` 에 바로 붙일 형태다.

쿼터는 검색어당 100 유닛 + 1 유닛이라 가끔 돌리기에 넉넉하다.

### 썸네일 (링크 미리보기)

텔레그램은 메시지 하나에 미리보기를 **하나만** 붙일 수 있다. 그래서 첫 항목의
링크로만 썸네일을 띄운다.

```yaml
link_preview:
  mode: first        # none 이면 썸네일 없음
  prefer: video      # any 면 메시지 첫 항목을 그대로 사용
  large: true        # false 면 작은 썸네일
  above_text: true   # false 면 본문 아래
```

`prefer: video` 는 메시지 순서와 무관하게 **영상 링크**로 썸네일을 만든다.
유튜브 링크는 썸네일이 확실히 잡히는 반면, Google 뉴스 링크
(`news.google.com/rss/articles/...`)는 리다이렉트라 미리보기가 비기
때문이다. 그래서 **뉴스 링크는 썸네일 대상에서 아예 뺀다** — 영상이 없으면
리다이렉트가 아닌 기사 링크를 찾고, 그마저 없으면 미리보기를 끈다.
빈 미리보기 카드가 붙느니 없는 편이 낫다.

썸네일이 안 뜨면 그 회차에 **영상이 하나도 없었을 가능성이 높다.** 구독
채널을 걸지 않은 주제는 위의 `youtube_search` 로 영상이 들어온다.

### 관심사 반영

`keywords` 의 가중치를 올리면 그 주제가 우선 선택되고, `exclude` 에 넣은
단어가 제목에 있으면 아예 빠진다.

## 로컬에서 돌려보기

```bash
python3 -m venv .venv
```

## 지금 바로 한 번 보내기

Actions 화면을 열 수 없을 때는 `.trigger` 파일을 건드려 푸시하면 발송이 돈다.

```bash
# 첫 줄이 회차다. 슬롯 이름만 쓰거나 <설정>:<슬롯> 으로 적는다
echo "evening"    > .trigger && git commit -am "발송" && git push
echo "food:lunch" > .trigger && git commit -am "발송" && git push

# 둘째 줄에 force 를 넣으면 이미 보낸 항목도 다시 보낸다 (--ignore-seen)
printf 'food:lunch\nforce\n' > .trigger && git commit -am "테스트 발송" && git push
```

경로 필터가 걸려 있어 다른 파일만 바꾼 푸시로는 발송되지 않는다. 이 경로가
필요 없으면 `digest.yml` 의 `push:` 블록을 지운다.

## 모바일 어드민 페이지

발송 시각·항목 수·키워드·제외어를 휴대폰에서 고친다. 채널 목록은
`config*.yaml` 에 그대로 두고, 페이지는 `settings.yaml` 만 덮어쓴다.

### 주소

`https://<사용자>.github.io/lookbook/`

### 켜기 (한 번)

1. 저장소 **Settings → Pages → Source: GitHub Actions**
2. **Actions → 어드민 페이지 배포 → Run workflow** (이후로는 `docs/` 가
   바뀔 때마다 저절로 배포된다)
3. 위 주소로 접속한 뒤 맨 위
   **먼저 GitHub 토큰을 넣어주세요** 카드에 fine-grained PAT 입력
   (토큰이 저장되면 이 카드는 한 줄로 접힌다)
   - 이 저장소 하나만, **Contents: Read and write** 권한만
   - 브라우저 localStorage 에만 저장되고 커밋되지 않는다

**주소를 열었는데 README 가 보이면** Pages Source 가 `Deploy from a branch`
(루트) 로 바뀐 것이다. 루트에 `index.html` 이 없으면 GitHub 이 `README.md` 를
대신 보여준다. 저장소 루트의 `index.html` 이 이 경우 `docs/` 로 넘겨주므로
그대로 두면 되고, `Source: GitHub Actions` 로 되돌려도 된다. 어느 쪽이든
같은 주소로 열린다.

### 데스크탑

같은 주소가 화면 폭에 따라 달라진다. 별도 페이지를 두지 않는 이유는
둘로 나누면 고칠 때마다 어긋나기 때문이다.

- 900px 이상 — 주제 카드가 여러 열로 깔리고(1440px 에서 3열),
  아래 막대가 오른쪽 아래에 뜬다
- <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>S</kbd> 로 저장

### 즐겨찾기

<kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>D</kbd>, 또는 주소창의 자물쇠를 즐겨찾기
바로 끌어다 놓는다. 즐겨찾기 바는 <kbd>Ctrl</kbd>/<kbd>⌘</kbd>+
<kbd>Shift</kbd>+<kbd>B</kbd>. 파비콘이 있어 바에서 아이콘으로 찾을 수 있다.
같은 안내가 페이지의 고급 설정에도 있다.

### 쓰기

화면은 위에서부터 **주제 추가 → 주제별 카드 → 고급 설정** 순이다.

- **주제 추가** — 맨 위. 말 하나를 넣으면 그 말로 구글 뉴스를 찾는 검색어가
  잡히고, 불러온 구독 목록에서 이름이 맞는 채널이 붙는다.
- **주제 카드** — 보낼 시간마다 제목·발송 스위치·시각·기사 수·영상 수,
  그리고 **지금 테스트 발송**. **＋ 보낼 시간 추가** 로 한 주제에 시간을
  몇 개든 둘 수 있고 **이 시간 삭제** 로 뺀다. 키워드·채널·블로그는 카드
  아래 접힌 줄(`키워드 n · 채널 n · 블로그 n`)을 펴야 나온다.
- **고급 설정** — Google Drive 에서 구독 목록 가져오기, 공통 제외어.

접힌 패널 맨 아래에 **주제 삭제** 가 있다. 마지막 시간을 지울 때도 주제째
지울지 물어본다 — 보낼 시간이 없는 주제는 남겨봐야 아무것도 하지 않는다.
config 파일이 있는 주제를 지워도 파일은 그대로 두고 발송만 멈춘다.

보낼 시간은 몇 개든 둘 수 있다. 발송을 거는 것은 `settings.yaml` 의
`slots` 뿐이라, 시간을 더하면 config 에 없는 회차가 생기고 그대로 돈다.
지우면 그 회차만 사라진다 — config 파일의 `slots:` 에 남아 있어도
`settings.yaml` 에 없으면 발송되지 않는다.

**바꾸면 알아서 저장된다.** 값을 건드리고 1.2초 뒤 `settings.yaml` 이
커밋되고, 화면 오른쪽 위가 `바뀜 → 저장하는 중… → 저장됨 09:41` 로 바뀐다.
화면 아래 알림도 뜨므로 어디까지 스크롤했든 결과가 보인다. 저장을 앞당기려면
**저장**, 저장소 쪽 값을 다시 가져오려면 **새로고침** 을 누른다.

다른 곳에서 먼저 `settings.yaml` 이 바뀌어 `sha` 가 어긋나면 최신 `sha` 를
받아 한 번 다시 민다. 편집하던 값이 조용히 사라지지 않는다.

### 키워드 = 검색어

칸이 둘이었다. 하나는 점수를 매기는 키워드, 하나는 구글 뉴스에 던지는
검색어. 같은 말을 두 번 넣게 되어 번거로웠다. 이제 **키워드 하나가 두 가지
일을 한다** — 그 말로 찾고, 그 말이 있으면 먼저 고른다.

검색어는 키워드에서 만들어 낸다. 하나씩 따로 걸면 키워드 수만큼 호출이
늘어나므로(유튜브 `search` 는 1회 100유닛) `OR` 로 묶어 회차당 한 번만
부른다. 너무 넓어지지 않게 **가중치 높은 순으로 6개**만 쓰고, 실제로 나가는
문장을 키워드 칸 아래에 그대로 적어 둔다.

`config*.yaml` 의 `sources.google_news` 는 그대로 남는다. 페이지에서 만든
검색어가 그 뒤에 붙는다.

### 키워드 순위

키워드는 **1·2·3순위** 상자에 나뉘어 있다. 저장은 그대로 숫자 가중치라
(1순위 = 3, 2순위 = 2, 3순위 = 1) 파이썬 쪽은 손대지 않았다.
`filter._score` 가 제목에 걸린 키워드의 가중치를 더해 점수를 매기고,
검색어도 **가중치 높은 순**으로 6개를 골라 만든다.

칩을 끌어다 다른 상자에 놓으면 순위가 바뀐다. HTML5 `draggable` 은 터치에서
동작하지 않아 **포인터 이벤트**로 만들었다 — 마우스·터치·펜이 같은 경로를
탄다. 칩에 `touch-action: none` 을 둬야 끄는 동안 화면이 따라 스크롤되지
않는다. 칩의 `×` 를 누른 것은 끌기로 치지 않는다.

새 키워드를 넣을 순위는 입력칸 위 선택으로 고른다. **추천 키워드는
3순위로 들어간다** — 사람이 고른 말이 아니므로 낮게 두고, 쓸 만하면
끌어 올리면 된다.

### 검색 결과는 키워드로 한 번 더 거른다

구글 뉴스도 유튜브도 검색어를 느슨하게 해석해 주제와 상관없는 것을 섞어
돌려준다. 예전에는 키워드가 **점수만 매길 뿐 아무것도 걸러내지 않아서**
그것들이 그대로 발송에 실려 갔다. `_score` 는 6시간 안에 올라온 항목에
`+2` 를 주므로, 주제와 무관한 새 기사가 관련 있는 옛 기사를 밀어내기도 했다.

이제 **검색으로 찾아온 항목은 키워드가 실제로 들어 있어야 후보가 된다.**

- `sources.google_news` · `sources.youtube_search` → 걸러낸다
- `sources.youtube`(채널) · `sources.rss`(피드) → **거르지 않는다.**
  사람이 채널을 믿고 고른 것이라 낱말이 안 걸려도 남긴다
- 제목뿐 아니라 본문 발췌도 본다. `이번 주 정리` 같은 맹숭한 제목의
  알맹이 있는 글까지 떨어뜨리지 않기 위함이다
- 낱말이 여럿인 키워드는 **붙어 있지 않아도 다 나오면** 걸린 것으로 본다.
  `남성 피부` 는 `남성의 피부 관리` 에도 걸리고 `여성 피부 관리` 에는 안 걸린다

```
[filter] 주제와 안 맞아 제외 37건 (검색으로 찾아온 것 중)
```

키워드에 없는 말로 쓰인 글은 걸러진다. `남성` 만 넣어두면 `남자 피부관리` 는
들어오지 않는다 — 그런 말이 자주 보이면 키워드로 함께 넣는다. 거르는 것
자체를 끄려면 `require_keyword: false`.

### 낱말이 여럿인 키워드

검색어를 만들 때 공백이 든 키워드는 따옴표로 묶는다.

```
남성 피부 OR 남성 화장품        → 남성 AND (피부 OR 남성) AND (화장품)
"남성 피부" OR "남성 화장품"    → 뜻대로
```

따옴표가 없으면 `OR` 가 낱말 단위로 붙어 전혀 다른 검색이 된다. 실제로
피부 주제가 이것 때문에 엉뚱한 결과만 받아왔다. 한 낱말짜리는 묶지
않는다 — 묶으면 어형이 조금 달라진 제목을 놓친다.

### 추천 키워드

주제를 만들면 추천이 바로 뜨고, 나중에는 **추천 키워드 보기** 로 부른다.
누르면 들어가고, **모두 추가** 로 다섯 개를 한 번에 넣는다. 넣은 말은
목록에서 빠지고 나머지는 남는다.

만드는 순서는 이렇다.

1. 자동완성 API — 브라우저에서 막힐 수 있어(CORS) 4초 안에 안 오면 버린다
2. `<주제> 추천/후기/입문/초보/리뷰/트렌드/꿀팁/순위/비교`
3. 불러온 구독 채널 이름에서 그 주제와 같이 쓰이는 말

1번이 실패해도 2·3번만으로 항상 다섯 개 이상 나온다. 자동완성이 되는지는
브라우저와 망 사정에 달려 있어 보장하지 않는다.

### 테스트 발송

슬롯의 **지금 테스트 발송** 을 누르면 저장하지 않은 값을 먼저 저장하고,
`.trigger` 에 `<설정>:<슬롯>` 과 `force` 를 써서 커밋한다. 워크플로의 푸시
경로가 걸려 그 회차만 즉시 돈다. `force` 가 있으므로 **이미 보낸 항목도
다시 온다** — 바꾼 설정이 어떻게 나오는지 바로 볼 수 있다.

토큰 권한은 `Contents: Read and write` 하나면 된다. Actions 권한은
필요 없다 — 파일을 커밋해서 워크플로를 깨우는 방식이기 때문이다.

### 새 주제 만들기

페이지 맨 위 **주제 추가** 에 말을 넣으면 그 말로 구글 뉴스를 검색하는
검색어가 잡히고, 받아둔 구독 목록에서 **채널명에 그 말이 든 채널이 최대
8개까지 자동으로 붙는다**(대소문자 무시). 붙은 채널은 접힌 패널이 열린 채
바로 보인다.

이름만 보고 맞추는 방식이라 `커피` 로는 `Coffee Break` 가 안 걸린다.
빠진 채널은 같은 패널의 검색창에서 찾아 넣으면 된다.

`config` 파일 없이 `settings.yaml` 만으로 도는 주제이므로 저장소를
직접 건드릴 일이 없다. 상태는 `state/<key>/` 에 자동으로 생긴다.

### 구독 목록은 Drive 에서 읽는다

Takeout 파일을 매번 올리지 않는다. 고급 설정에서 Drive 에 한 번 연결해두면
파일을 골라 읽고, 다음부터는 **다시 동기화** 한 번으로 최신 목록을 받는다.

- **zip 그대로 둬도 된다.** Takeout 이 만든 zip 안에서 구독정보 csv 만
  찾아 브라우저에서 푼다(`DecompressionStream`). 풀어놓은 csv 나 구글
  스프레드시트도 읽는다.
- 채널 ID 열의 위치는 언어판마다 달라서, 자리 대신 `UC` + 22자 형태로
  값을 보고 찾는다.

#### 한 번만 하는 준비

연결하기 전에는 **페이지 맨 위** 에 `구독 채널 불러오기` 카드가 뜬다.
연결하고 나면 그 카드는 사라지고 조작은 고급 설정 안으로 들어간다.

1. [Drive API 사용 설정](https://console.cloud.google.com/apis/library/drive.googleapis.com)
2. [**OAuth 동의 화면**](https://console.cloud.google.com/auth/overview) → 대상 `외부`
   → **테스트 사용자에 본인 계정 추가**
   `drive.readonly` 는 민감한 범위라, 테스트 사용자에 없으면 `access_denied` 가 난다.
3. **OAuth 클라이언트 ID** 만들기 → 유형 `웹 애플리케이션`
4. 승인된 자바스크립트 출처에 `https://<사용자>.github.io`
   — 뒤에 `/` 나 경로(`/lookbook`)를 붙이면 안 된다
5. 만들어진 클라이언트 ID 를 **맨 위 카드** 에 붙여넣기 (저장하면 곧바로
   Drive 파일 목록이 뜬다)

막히면 카드의 **연결 점검** 이 스크립트 로드·ID 형식·현재 출처를 적어준다.

클라이언트 ID 는 비밀값이 아니지만 이 기기의 localStorage 에만 둔다.
권한은 읽기 전용(`drive.readonly`) 하나이고, 액세스 토큰은 저장하지 않아
탭을 닫으면 사라진다.

### 목록은 커밋되지 않는다

받은 구독 목록은 **브라우저 localStorage 에만** 둔다. 이 저장소는 공개이므로
목록 전체를 올리지 않고, 주제에 실제로 넣은 채널만 `settings.yaml` 에
커밋된다. 기기를 바꾸면 Drive 에서 다시 받으면 된다.

### 발송 시각이 데이터인 이유

크론에 시각을 박아두면 페이지에서 바꿀 수 없다. 그래서 워크플로는
30분마다 깨어나 `settings.yaml` 을 보고 **지금 보낼 회차가 있는지**만
판단한다(`--due`). 이미 보낸 회차는 `state/schedule.json` 의 날짜로
걸러지므로 중복 발송되지 않고, 크론이 밀려도 3시간 안이면 따라잡는다.

## 다이제스트 여러 개 운영하기

설정 파일 하나가 다이제스트 하나다. 파이프라인·요약·썸네일은 공유하고
발송 이력만 분리된다.

| 설정 파일 | 주제 | 상태 | 슬롯 (KST) |
|---|---|---|---|
| `config.yaml` | 러닝 | `state/` | `morning` 08:00, `evening` 19:00 |
| `config.food.yaml` | 음식 | `state/food/` | `lunch` 12:30 |
| `config.fashion.yaml` | 패션 | `state/fashion/` | `night` 21:30 |

**보낼 시간의 개수는 config 파일이 정하지 않는다.** 발송을 거는 것은
`settings.yaml` 의 `slots` 뿐이라, 어드민 페이지에서 시간을 더하면
config 에 없는 회차가 생기고 그대로 돈다. 이력은 주제 단위로 묶이므로
같은 주제를 하루에 세 번 보내도 같은 기사가 두 번 오지는 않는다.

텔레그램 채팅방은 하나를 같이 쓴다.

**한 파일 안에서 슬롯마다 다른 소스를 쓰려면** 소스에 `tags` 를 달고
슬롯에서 고른다. 슬롯에 `tags` 가 없으면 모든 소스를 쓴다. 주제가
확실히 갈리면 태그 대신 파일을 나누는 편이 읽기 쉽다 — 패션과 음식도
그래서 각자 파일을 쓴다.

```yaml
sources:
  youtube:
    - name: 어느 맛집 채널
      channel_id: UC...
      tags: [food]
slots:
  lunch:
    tags: [food]     # 이 슬롯은 food 소스만 본다
```

새 다이제스트를 추가하려면 `config.<이름>.yaml` 을 만들고
`digest.yml` 의 크론과 `case` 문에 한 줄씩 넣는다. 상태는
`state/<이름>/` 에 자동으로 생긴다.

## 구독 채널에서 골라 담기

구독 목록에서 러닝·운동 채널만 뽑아 `config.yaml` 에 넣을 형태로 출력한다.

1. YouTube 설정 → 개인정보 보호 → **'모든 구독 정보 비공개'를 끈다**
   (구독 목록은 기본이 비공개이고, 비공개면 API 키로 읽을 수 없다)
2. `.subs-trigger` 에 본인 핸들을 적고 푸시

   ```bash
   echo "@myhandle" > .subs-trigger && git commit -am "구독 확인" && git push
   ```

3. Actions 로그에서 후보 목록을 확인하고 `config.yaml` 에 옮긴다
4. 끝나면 구독 정보를 다시 비공개로 되돌린다

아무것도 전송하지 않고 로그에만 출력한다.

## 잘 안 될 때

**Drive 연결이 `access_denied` 로 막힘**

`prompt: ""` 는 "동의 화면을 띄우지 말라"는 뜻이라, 한 번도 허락한 적이 없으면
구글이 묻지 않고 그대로 거부한다. 그래서 **첫 연결은 `prompt: "consent"`**,
허락을 받은 뒤부터만 조용히 받는다(`g_granted` 로 기억).

코드가 아니라 설정 쪽 `access_denied` 라면 OAuth 동의 화면의 **테스트 사용자**
에 로그인한 계정이 없는 경우다. 위 준비 2번을 확인한다.

| 코드 | 할 일 |
|---|---|
| `access_denied` | 테스트 사용자에 계정 추가 |
| `unregistered_origin` | 승인된 자바스크립트 출처 확인 (`/` 없이) |
| `invalid_client` | 클라이언트 ID 다시 복사 |
| `popup_failed_to_open` | 팝업 차단 해제 |

페이지 머리말에 빌드 날짜가 찍힌다. 고친 판을 보고 있는지 여기서 확인한다.

**어드민 페이지에서 `저장하지 못했습니다 403`**

`Resource not accessible by personal access token` — fine-grained PAT 가 이
저장소에 대해 Contents 쓰기를 못 받았다는 뜻이다. 원인은 둘 중 하나다.

1. **Repository access** 의 Only select repositories 목록에 이 저장소가 없다
2. **Repository permissions → Contents** 가 `Read-only` 다

읽기는 공개 저장소라 토큰 없이도 되기 때문에, 화면은 정상으로 보이다가
저장할 때 처음 막힌다. 고친 뒤 **Update** 를 누르면 되고 새 토큰을 만들
필요는 없다.

`GET /repos/{owner}/{repo}` 의 `permissions.push` 로는 판별할 수 없다.
그 값은 **토큰이 아니라 사용자가** 저장소에 갖는 권한이라, 본인 저장소면
언제나 `true` 다. 페이지의 **점검** 버튼은 그래서 같은 내용을 그대로 다시
올려보는 식으로 확인한다 — 실제로 써 봐야만 알 수 있다.

| 응답 | 뜻 | 할 일 |
|---|---|---|
| 401 | 토큰 만료·오타 | 새로 발급해 다시 입력 |
| 403 | 이 저장소에 대한 Contents 쓰기 없음 | 위 1·2 확인 |

저장에 실패해도 고친 값은 브라우저에 남는다. 권한을 고치고 **다시 확인**
을 누르거나, 새로고침하면 되살아난다.

**`TELEGRAM_BOT_TOKEN 이 설정되어 있지 않습니다`**

시크릿이 등록되지 않았거나 워크플로가 읽을 수 없는 자리에 있다. 확인할 것:

- **Settings → Secrets and variables → Actions** 의 **Secrets** 탭인지.
  같은 화면의 **Variables** 탭에 넣으면 `secrets.` 로 읽히지 않는다.
- **Repository secrets** 목록에 있는지. Environment secrets 는 잡에
  `environment:` 를 지정해야 읽힌다.
- 이름이 정확히 `TELEGRAM_BOT_TOKEN` 인지 (오타, 앞뒤 공백 주의).
- 왼쪽 사이드바에서 Codespaces 나 Dependabot 시크릿 화면에 넣지 않았는지.

로그의 `env:` 블록에 `TELEGRAM_BOT_TOKEN:` 이 빈칸으로 보이면 못 찾은 것이고,
`***` 로 보이면 제대로 전달된 것이다.

등록 화면 바로가기:
`https://github.com/<소유자>/<레포>/settings/secrets/actions`

**시크릿 이름을 로그에 찍어 확인하고 싶더라도 `toJSON(secrets)` 는 쓰지
않는다.** 시크릿 컨텍스트 전체를 읽는 워크플로는 GitHub 이 승인 대상으로
분류해서, 실행할 때마다 "Approve and run" 을 눌러야 한다. 이름이 의심되면
프리플라이트 단계가 어느 시크릿이 비었는지 알려주므로 그걸 보면 된다.

**영상이 하나도 안 올 때**

실행 로그 끝의 `문제가 있는 소스` 목록을 본다. 로그에는 채널마다
`channel_id=UC... (canonical)` 처럼 어느 표지에서 ID를 뽑았는지도 찍힌다.

- 피드가 **404** 면 channel_id 가 그 채널의 것이 아닐 가능성이 높다.
  `state/channels.json` 에서 해당 항목을 지우면 다음 실행에서 다시 찾는다.
- **500** 은 대개 일시적이라 자동으로 한 번 재시도한다. 계속되면 유튜브 쪽
  문제일 수 있으니 다음 회차를 기다려 본다.
- 채널 주인이 핸들을 바꿨다면 `config.yaml` 의 주소를 고친다.

**`최근 대화 기록이 없습니다`**

봇에게 보낸 메시지가 없거나 24시간이 지났다. BotFather 가 알려준 `@사용자명`
이 맞는지 확인하고 메시지를 다시 보낸 뒤 워크플로를 재실행한다.

## 알아둘 점

- **크론은 정시를 보장하지 않는다.** 러너 부하에 따라 5~15분 밀린다.
  이를 감안해 크론을 목표 시각보다 10분 앞에 잡아뒀다.
- **60일간 커밋이 없으면 스케줄 워크플로가 자동 비활성화된다.**
  매 발송마다 `state/seen.json` 을 커밋하므로 이 문제는 자연히 피해간다.
- 피드 하나가 죽어도 나머지는 정상 발송된다. 실패한 소스는 로그에 남는다.
- 보낼 새 항목이 없으면 메시지를 보내지 않고 조용히 넘어간다.
- **요약은 선택한 항목에만, 한 번의 요청으로 처리한다.** 걸러낸 항목은
  번역하지 않고, 항목마다 따로 호출하지도 않는다.
