# 인스타 장소 아카이브 봇

텔레그램에 인스타그램 게시물 URL 을 보내면 장소를 찾아
**구글 지도 저장 목록**(`📍서울 성수` 처럼 동네 상권별)과 **옵시디언**에 저장한다.
집 Windows PC 에서 상시 실행한다. 설계와 결정 배경은 [PLAN_PLACE_ARCHIVE.md](../PLAN_PLACE_ARCHIVE.md).

```
URL → 캡션 수집 → Gemini 로 장소 추출 → 카카오 로컬로 주소·좌표 확인
    → 구글 지도 '저장' 자동 클릭 → 옵시디언 노트 + 지역별 목록 노트 → 텔레그램 답장
```

## 준비물 (키 2개 + 선택 1개)

비밀번호는 필요 없다. 아래 키만 설치 중에 PC 에 직접 입력한다.
**채팅이나 레포에 붙여넣지 않는다.**

| 키 | 받는 곳 |
|---|---|
| 텔레그램 봇 토큰 | 텔레그램 `@BotFather` → `/newbot` → 이름 지정 → `123456:ABC...` 형태 토큰. 러닝 다이제스트 봇과 **다른 새 봇**을 만든다 |
| Gemini API 키 | aistudio.google.com → Get API key (러닝 다이제스트의 `GEMINI_API_KEY` 재사용 가능). Claude 를 쓰려면 `places.yaml` 의 `extract.provider: claude` + `ANTHROPIC_API_KEY` |
| 카카오 REST API 키 (선택) | developers.kakao.com → 내 애플리케이션 → 애플리케이션 추가 → 앱 키의 **REST API 키**. 앱 설정에 '카카오맵' 사용 설정이 있으면 켠다 |

카카오 키가 없어도 봇은 돈다. 대신 국내 장소의 위치를 캡션만 보고 정하므로
동네 상권이 비거나(`📍서울` 목록으로 저장), 구글 지도에서 다른 지점이 저장되거나,
주소·좌표가 빠질 수 있다. 나중에 `places.env` 의 `KAKAO_REST_API_KEY=` 뒤에 키를 적고
`설치하기.bat` 을 다시 실행하면 그 뒤로 저장하는 장소부터 정확해진다.

## 설치 (한 번)

1. 파이썬 3.10 이상, 구글 드라이브 데스크톱 앱(vault 동기화 중), 크롬이 있는 PC
2. 이 레포 전체를 PC 에 받는다 (GitHub → Code → Download ZIP 후 압축 풀기, 또는 `git clone`)
3. `scripts\windows\places\설치하기.bat` 더블클릭
   - 키 입력 (카카오는 Enter 로 건너뛰기 가능) → vault 경로 입력 (예: `G:\내 드라이브\Obsidian\MyVault`)
   - 크롬 창이 뜨면 **직접 구글 로그인** → 콘솔로 돌아와 Enter
4. 텔레그램에서 새 봇에게 아무 말이나 보내면 채팅방 ID 를 답한다
5. 그 숫자를 `%USERPROFILE%\.lookbook\places.env` 의 `TELEGRAM_CHAT_ID=` 뒤에 적고
   `설치하기.bat` 을 한 번 더 실행 (봇 재시작)

이후에는 PC 에 로그인할 때마다 자동으로 켜진다.
이 채팅방 외의 메시지는 무시한다.

## 먼저 샘플로 시험하기

설치 3단계 후, 레포 폴더에서 PowerShell 로 (저장 없이 분석만):

```powershell
$py = "$env:USERPROFILE\.lookbook\places-venv\Scripts\python.exe"
& $py -m places try https://www.instagram.com/p/Ddxt9nOkeas/ https://www.instagram.com/p/DejKUQwk6NU/ https://www.instagram.com/p/Dei7h14Gh-c/
```

수집 경로(`embed`/`og`/실패), 캡션 원문, 찾은 장소가 출력된다.
`--save` 를 붙이면 구글 지도·옵시디언에 실제로 저장한다.

## 쓰는 법

| 보내는 것 | 동작 |
|---|---|
| 인스타 URL (여러 개 가능) | 분석 후 바로 저장, 결과 답장 |
| URL + 캡션 텍스트 | 수집을 건너뛰고 보낸 캡션으로 분석 |
| 캡션 텍스트만 | 직전에 캡션 수집이 실패한 게시물에 이어서 적용 |
| `/recent` `/stats` | 최근 저장 · 지역별 개수 (메뉴 버튼에서는 뺐다) |
| `/undo` | 마지막 게시물 저장 취소 (구글 지도 목록에서는 직접 지운다) |
| 📎 → **위치** (휴대폰 GPS) | 지금 있는 곳에서 가까운 저장 장소 20곳을 ① 거리순, ② 평점순(댓글 수 표기) 두 구간으로 (길찾기·지도 링크) |
| `근처 카페` · `/near 맛집 3` | 무엇을 찾는지 말하면 '📍 내 위치 보내기' 버튼이 뜬다. 누르면 그 조건으로 추천 |
| 화면 아래 **메뉴 버튼** (2줄) | ☕ 근처카페 · 🍽 근처맛집 · 🏛 근처장소 / 🔄 동기화 · ↩️ 저장취소. 항상 떠 있고 글자 명령과 같다. `/stats` `/status` `/retry` 는 글자나 입력창 옆 `/` 메뉴로 쓴다 |
| `/근처카페` `/근처맛집` `/근처장소` | 누르면 📍 내 위치 보내기 버튼이 바로 뜬다. 한 번 누르면 그 조건(카페 · 식당 · 명소)으로 가까운 곳을 알려 주고 메뉴가 돌아온다. 명소 = 전시/공간 + 자연/산책 (가볼 만한 곳) |
| `/status` `/retry` | 작동 확인 · 지도에 저장 못 한 장소 다시 저장 |
| `/sync` | 구글 지도 앱에서 **직접 저장한 장소**를 봇 기록에 가져온다 ([아래](#구글-지도-앱에서-직접-저장한-장소-sync)) |
| `/sync 예` · `/sync 아니오` | 새 장소를 시 단위 목록(`📍경기 성남시`)에도 넣을지 답한다 (한 번만 묻는다) |

## 내 주변 추천

휴대폰에서 텔레그램으로 위치를 보내면, **저장해 둔 장소 중 가장 가까운 20곳**을 알려 준다 (직선거리). 답장은 두 구간이다.
① **가까운 순** 20곳 · ② **평점 높은 순** — 가까운 60곳 중 상위 20곳, `★4.7 (댓글 1,234)` 처럼 평점과 댓글 수를 같이 보여 준다.
평점은 댓글 수로 보정해 정렬한다 (평균 4.3 의 가짜 댓글 20개를 더해 평균: 5.0 이 댓글 1개뿐이면 4.7 이 댓글 1,000개인 곳보다 아래).
평점·댓글 수는 `/sync` 가 구글 지도 목록 줄에서 읽어 저장해 두므로, **처음 한 번 `/sync` 를 보내야** ②가 채워진다 (이후 `/sync` 때마다 갱신).
`근처 카페`·`/near 미쉐린 3`·`/near 맛집 10` 처럼 분류(식당·카페·바·베이커리·숙소·쇼핑·전시·산책)나
`미쉐린` 같은 태그, 개수(기본 20, 최대 50)를 같이 말할 수 있다. 말한 뒤 10분 안에 보낸 위치에만 적용된다.

- 기준 장소는 봇이 아는 저장 장소다 (인스타·미쉐린으로 넣은 것 + 기존 구글 지도 목록에서 가져온 것).
  **구글 지도 앱에서 직접 저장한 장소는 `/sync` 를 보내야 반영된다** (아래).
- 위치는 거리 계산에만 쓰고 저장하지 않으며, 로그에도 좌표를 남기지 않는다.
- 좌표는 저장할 때 구글 지도에서 읽어 둔다. 이전에 저장한 장소는 한 번 `& $py -m places coords`
  (로그인 없는 브라우저로 하나씩 열어 읽는다. 봇을 끄지 않아도 된다). 결과는 `%USERPROFILE%\.lookbook\coords.json`.

답장 표시: `✅지도` 자동 저장 성공 · `⚠️자동저장 실패 · 지도에서 저장` 링크를 눌러 직접 저장 ·
`⚠️위치 확인 필요` 카카오에서 확실한 매장을 못 찾음

## 구글 지도 앱에서 직접 저장한 장소 (`/sync`)

휴대폰 구글 지도에서 저장한 장소는 봇의 기록(`places.json`)에 없어서 '내 주변 추천'에 안 나온다.
텔레그램에서 `/sync` 를 보내면 봇이 구글 지도 **저장됨 탭의 목록을 다시 읽어 봇이 모르는 장소만** 가져온다.

1. 목록마다 장소 줄의 이름만 읽어 이미 아는 이름과 견준다 (전부 열면 수백 곳이라 오래 걸린다).
2. 새 이름만 장소 페이지를 열어 이름·주소·좌표를 읽는다. 열어 보니 이미 아는 장소(이름이 비슷하고
   300m 안, 또는 같은 지도 ID)면 새로 만들지 않고 목록 이름만 보태며, 다음부터는 열지 않는다.
3. 새 장소는 `places.json`(`gmaps_list` = 직접 저장한 목록 이름 그대로), `coords.json`(좌표),
   옵시디언 노트(`시도\동네\이름.md`)에 들어가고 바로 '내 주변 추천' 후보가 된다.

답장 예: `🆕 봇이 몰랐던 새 장소 3곳 저장` + 이름·분류·동네·원래 목록. 진행 메시지가 단계(목록 읽기 →
새 장소 찾기 → 노트·좌표 저장)와 진도율을 보여 준다. 목록이 수십 개면 1~3분, 새 장소가 많으면 곳당 몇 초 더 걸린다.

- **시 단위 목록**: 새 장소를 `📍경기 성남시` 같은 목록에도 넣을지 처음 한 번만 묻는다.
  `/sync 예` 면 지금까지 모은 새 장소를 넣고 이후로는 연 자리에서 바로 넣는다, `/sync 아니오` 면 직접 저장한
  목록 이름 그대로 둔다. 답은 `places.json` 에 기억한다.
- **지우지 않는다.** 구글 지도 목록·장소를 지우거나 목록에서 빼지 않는다 (이미 든 목록은 건드리지 않는다).
- 못 연 장소는 `⚠️ 못 연 장소` 로 알려 주고 다음 `/sync` 에서 다시 시도한다.
- 이름이 같은 다른 지점을 이미 저장해 뒀다면, 이름이 정확히 같은 새 지점은 놓칠 수 있다
  (이름만 보고 아는 장소로 건너뛴다).

봇이 쓰는 크롬 프로필은 동시에 둘이 못 열어서, 봇이 켜져 있으면 텔레그램 `/sync` 로 하고
(봇 안에서 돌고 `places.json` 도 봇이 쓴다), 터미널에서 돌리려면 봇을 끈 상태에서:

```powershell
& $py -m places sync                # 새 장소 가져오기 (처음엔 시 목록 질문이 뜬다)
& $py -m places sync --city yes     # 시 단위 목록에도 넣기 (no 면 안 넣기. 한 번 정하면 기억)
```

## 저장 위치

| 무엇 | 어디 |
|---|---|
| 장소 노트 | `vault\Places\서울\성수\<장소명>.md` (frontmatter: 주소·좌표·지도 링크·출처 게시물) |
| 지역별 목록 | `vault\Places\장소 목록.md` (지도 미저장 장소 표시) |
| 처리 기록 | `%USERPROFILE%\.lookbook\places.json` — 공개 레포라서 기록은 레포에 올리지 않는다 |
| 로그 | `%USERPROFILE%\.lookbook\places.log`, 지도 저장 실패 스크린샷 `gmaps_fail_*.png` |

노트 아래쪽 `## 메모` 에 쓴 내용은 같은 장소가 다시 저장돼도 지워지지 않는다.
동네 이름 보정(서교동 → 홍대 등)은 `places.yaml` 의 `region_alias`.

## 구글 지도 목록 이름

저장할 때 구글 지도에 뜨는 주소로 정한다 (`places.yaml` 의 `gmaps.list_unit: city`).

| 주소 | 목록 |
|---|---|
| 시 (경기도 성남시 …) | `📍경기 성남시` |
| 군 (강원도 평창군 …) | `📍강원` |
| 특별·광역시 (서울특별시 …) | `📍서울` |
| 해외 | 나라만, `📍일본` `📍인도네시아` |

미쉐린 가이드 같은 **장소 목록**을 한 번에 넣으려면 (봇을 끈 상태에서):

```powershell
& $py -m places addlist "$env:USERPROFILE\.lookbook\lists\michelin.json"           # 확인만: 구글 지도가 연 이름·주소를 보여줌
& $py -m places addlist "$env:USERPROFILE\.lookbook\lists\michelin.json" --apply   # 확인을 통과한 장소를 저장
```

JSON 형식과 이름이 안 맞을 때 고치는 법(`query`·`alt`)은 `places/addlist.py` 맨 위 설명. 이름·주소의
시도가 목록과 안 맞으면 저장하지 않고 알려 준다. 목록 파일은 개인 기록이라 레포 밖에 둔다.

기존 목록을 이 규칙으로 다시 정리하려면 (봇을 끈 상태에서, 기존 목록은 지우지 않는다):

```powershell
& $py -m places reorg --sample 2   # 목록마다 2곳만 미리보기
& $py -m places reorg --apply      # 전체 (장소 수백 곳이면 1시간 남짓). 옵시디언 노트도 만든다
& $py -m places reorg --retry      # 실패한 곳만 다시
```

## 알아둘 위험

- **구글 지도 자동 저장은 비공식 방식이다.** 구글 화면이 바뀌면 실패하고(그때는 링크로 안내),
  자동화 탐지로 계정에 보안 확인이 뜰 수 있다. 로그인이 풀리면 봇을 끄고
  `& $py -m places login` 으로 다시 로그인한다 (`설치하기.bat` 을 다시 실행해도 된다).
- 저장할 때 크롬 창이 잠깐 뜬다 (`gmaps.headless: true` 로 숨길 수 있지만 구글이 막을 가능성이 커진다).
- 인스타는 로그인 없이 보면 카드뉴스 슬라이드를 안 보여준다(가게 이름이 이미지에만 있으면 못 찾음).
  봇 전용 크롬에 인스타 로그인을 한 번 해 두면(`& $py -m places iglogin`, 창이 뜨면 직접 로그인)
  게시물 슬라이드를 넘겨 가며 이미지를 Gemini 에 함께 보낸다. **자동화 탐지로 계정이 제한될 수 있어
  부계정을 권장한다.** 로그인이 풀리면 로그인 없는 경로로 자동으로 넘어가고, 그때 로그에 다시 로그인 안내가 남는다.
  그래도 못 찾으면 캡션·가게 이름을 복사해 보내면 된다.
